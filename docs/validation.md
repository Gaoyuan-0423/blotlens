# 验证记录与后续研究

软件可运行、固定 ROI 算术正确、视觉定位准确和对审稿有帮助是四种不同证据。本文件分开记录，未执行的项目不计为通过。

## 已执行：独立数值真值与 ImageJ 对照

2026-10-10（Asia/Shanghai），在 macOS / arm64、Node.js 22.22.0、Java 8u351、ImageJ 1.53a 上执行：

```sh
node --import tsx scripts/evaluate.ts \
  --imagej-jar /Applications/ImageJ.app/Contents/Java/ij.jar \
  --out docs/validation-evidence.json
```

结果和被检查源码 SHA-256 见 [validation-evidence.json](validation-evidence.json)。运行完成 105 个断言。独立构造的 96 × 90 灰度图包含 3 行 × 3 泳道的已知常量矩形，每个条带上下背景具有不同强度；真值直接来自区域面积与指定常量，不来自应用的积分函数。

检查包括原始信号和、背景合并均值、净信号、泳道配对、内参变化后的相对值、零内参、负净值、透明像素与 RGB 灰度转换。两组目标相对值分别为 `[1, 1, 1]` 与 `[1, 0.25, 3]`，用来避免仅测试“内参恒定”的简单情形。

脚本将独立 PNG 和固定 ROI 交给安装的 ImageJ 实际测量，使用 `getRawStatistics`。9 个条带的信号和、背景均值、净信号与本工具结果的最大绝对差为 **0**。这证明该固定 8-bit 合成输入下的数学一致性，不证明自动定位准确、背景选择合理或真实 WB 定量有效。PNG 内容哈希及 9 组实际测量值均记录于证据 JSON。

ImageJ 1.x 使用 `-batch` 执行，不强制设置 `java.awt.headless=true`，因为本机版本的图像打开过程仍初始化 AWT。其他机器需要可用的 Java 与 ImageJ；纯无显示 Linux 环境可能需要显示支持。脚本失败会以非零状态退出，不把未执行的外部比较记为通过。参见 [ImageJ CLI](https://imagej.net/ij/docs/guide/146-18.html) 和 [宏函数文档](https://wsr.imagej.net/ij/developer/macro/functions.html)。

只运行不依赖 ImageJ 的检查：

```sh
npm run evaluate
```

检查保存分析的结构及编辑记录摘要：

```sh
npm run evaluate -- --record /absolute/path/analysis.json
```

可重复传入 `--record`。摘要中的修改框数量是相对于首个已保存历史快照的差异，不保证等同于模型最初输出，也不能作为准确率。该命令不重新调用模型、不解码导入分析中的图像进行再次测量。

## 尚未完成的研究验证

- **视觉识别：** 尚无真实模型调用结果或留出数据集准确率。固定模型、服务、提示词和日期，收集有使用权限的截图；分别记录面板、蛋白行、泳道和标签错误，以及人工修改次数和时间。
- **真实图片一致性：** 固定灰度、ROI、背景与归一化方案，在真实截图上与人工 ImageJ 操作比较，报告绝对／相对偏差和失败个案。另行测试自动 ROI，避免把定位误差混同积分误差。
- **稳健性：** JPEG 压缩、缩放、低分辨率、非均匀背景、近黑截断、黑框、水印、倾斜组名、弱带、缺失条带和多面板歧义。记录是否正确拒绝／提示以及经人工修正能否完成，不只统计成功导入。
- **审稿效用：** 与纯肉眼检查比较趋势判断、耗时及错误，事先规定数据集、任务、终点和评价者流程。单张代表图与重复汇总图存在合理差异，不把任何差异自动定义为论文错误。
